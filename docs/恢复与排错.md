# 故障恢复与排错手册

本文只讲"出问题了怎么办"。安装和配置请先看 [../README.md](../README.md)。

---

## 0. 一分钟自救表

| 症状 | 一句话解法 |
|---|---|
| 开机黑屏几秒后自动进 Windows | 正常。把 `DEBUG=1` 打开看日志 |
| 开机卡住/停在厂商 logo 不动 | 断电重启；进 BIOS 关掉这项启动；或按下面 §2 恢复 |
| 出现 "no boot target could be loaded" | `bootmgfw-orig.efi` 丢了 → §2 |
| 无限重启 | 配置里 `CHAINLOAD` 指向了自己 → §3 |
| 动画不见了但系统正常 | Windows 更新覆盖了 shim → 重跑安装脚本；或 §4 |
| 显示 Secure Boot 相关错误 | §5 |

**最重要的原则**：只要 ESP 上的 `\EFI\Microsoft\Boot\bootmgfw-orig.efi` 还在，
你就一定能救回来，而且只需要**改一个文件名**。

---

## 1. 先确认 ESP 里有什么

用管理员 PowerShell：

```powershell
# 找到 ESP 并临时分配盘符 S
$p = Get-Partition | Where-Object { $_.GptType -eq '{c12a7328-f81f-11d2-ba4b-00a0c93ec93b}' }
Add-PartitionAccessPath -DiskNumber $p.DiskNumber -PartitionNumber $p.PartitionNumber -AccessPath 'S:'

dir S:\EFI\BootAnim
dir S:\EFI\Microsoft\Boot\bootmgfw*
```

正常情况下应该看到：

```
S:\EFI\BootAnim\bootanim.efi
S:\EFI\BootAnim\anim.baa
S:\EFI\BootAnim\bootanim.cfg
S:\EFI\Microsoft\Boot\bootmgfw.efi          <- 我们的 shim（带 BOOTANIM 标记）
S:\EFI\Microsoft\Boot\bootmgfw-orig.efi     <- 微软原版（救命的那个）
```

用完记得撤销盘符：

```powershell
Remove-PartitionAccessPath -DiskNumber $p.DiskNumber -PartitionNumber $p.PartitionNumber -AccessPath 'S:\'
```

判断 `bootmgfw.efi` 是不是我们的 shim：

```powershell
$b = [IO.File]::ReadAllBytes('S:\EFI\Microsoft\Boot\bootmgfw.efi')
$needle = [Text.Encoding]::ASCII.GetBytes('BOOTANIM-EFI-LOADER-MARKER')
# 手工看：用十六进制编辑器搜索 BOOTANIM 也行
```

## 2. 系统起不来了：改回原版引导程序

### 2.1 情况 A：还能进 Windows（只是没动画 / 有报错）

管理员 PowerShell：

```powershell
cd <项目>\install
.\Uninstall-BootAnim.ps1
```

### 2.2 情况 B：进不了 Windows（黑屏/卡死/自动重启）

用 **Windows 安装 U 盘**（或 Windows PE）启动：

1. 选择语言 → **修复计算机** → **疑难解答** → **高级选项** → **命令提示符**

2. 找到并挂载 ESP：

```bat
diskpart
list disk
select disk 0
list partition
rem 找到类型为"系统"、容量约 100~500MB 的那个分区
select partition 1
assign letter=S
exit
```

3. **核心的一步 —— 把备份改回来**：

```bat
ren S:\EFI\Microsoft\Boot\bootmgfw-orig.efi bootmgfw.efi
```

   如果提示"文件已存在"，说明当前那个是坏的/是我们的 shim，先删再改：

```bat
del S:\EFI\Microsoft\Boot\bootmgfw.efi
ren S:\EFI\Microsoft\Boot\bootmgfw-orig.efi bootmgfw.efi
```

4. 顺手重建一下引导（可选，但推荐）：

```bat
bcdboot C:\Windows /s S: /f UEFI
```

   > `C:` 是 Windows 所在盘在本环境里的盘符，用 `dir C:\Windows` 确认一下。

5. `exit` 退出，重启。

### 2.3 情况 C：`bootmgfw-orig.efi` 也没了

那就需要从别处拿一份 `bootmgfw.efi`：

- **最快**：另一台同版本 Windows 的机器上复制
  `C:\Windows\Boot\EFI\bootmgfw.efi`（这是 Windows 自带的副本！），
  放到 ESP 的 `\EFI\Microsoft\Boot\bootmgfw.efi`。
- 或者只跑 `bcdboot C:\Windows /s S: /f UEFI` —— 它会把引导文件（包括
  `bootmgfw.efi`）重新写到 ESP 上，这也是最省事的做法。

> `C:\Windows\Boot\EFI\bootmgfw.efi` 是 Windows 长期保留的引导程序副本，
> 只要系统盘还在，就永远有一份可用的原版。

## 3. 无限重启 / 卡在动画

原因：`bootanim.cfg` 里的 `CHAINLOAD` 指向了 BootAnim 自己。

程序的自我保护（自链保护）会拒绝加载自己并转去试备用目标，正常情况下不会死循环；
但如果 `CHAINLOAD` 和 `CHAINLOAD_FALLBACK` **都**指向自己，它就会打印
`FATAL - no boot target could be loaded` 然后返回错误码让固件试下一个启动项。
如果你的固件启动顺序里只有 Windows 一项，就会表现得像"卡住"。

处理：按 §2.2 进恢复环境，把 ESP 上的 `\EFI\BootAnim\bootanim.cfg` 删掉
（删掉后程序使用内置默认值，默认值是对的），或者把它改成：

```ini
CHAINLOAD=\EFI\Microsoft\Boot\bootmgfw-orig.efi
CHAINLOAD_FALLBACK=\EFI\Microsoft\Boot\bootmgfw.efi
```

也可以在恢复环境的命令提示符里直接删：

```bat
del S:\EFI\BootAnim\bootanim.cfg
```

## 4. 系统更新后又没动画了

Windows 的功能更新（大版本升级）会重写 `bootmgfw.efi`，把我们的 shim 冲掉。
这**不会**造成任何损坏，`bootmgfw-orig.efi` 也还在。

处理：重新运行安装脚本即可。

```powershell
cd <项目>\install
.\Install-BootAnim.ps1
```

> `dist\bootanim.efi` 如果被删了，需要重新编译一次。

## 5. Secure Boot 相关

**现象**：动画不出现，`DEBUG=1` 时看到 `blocked by Secure Boot`，或固件直接
拒绝启动并跳到下一个启动项。

原因：`bootanim.efi` 没有微软或你机器 `db` 里的证书签名。

三种选择：

1. **关掉 Secure Boot**（BIOS 里 `Secure Boot → Disabled`）。
   注意：关掉之后 BitLocker 可能会要求输入恢复密钥 —— 关之前先
   `Suspend-BitLocker -MountPoint C: -RebootCount 1`。
2. **自己签名**：把自己生成的证书导入到固件的 `db`（各厂商入口不一样，
   通常在 BIOS 的 Key Management 里），然后：
   ```powershell
   # 需要 Windows SDK 的 signtool
   signtool sign /fd SHA256 /a /f mycert.pfx /p <密码> dist\bootanim.efi
   ```
3. **干脆不装**，用 UEFI Shell 手动运行（也需要关 Secure Boot）。

## 6. 画面类问题

### 6.1 有画面但颜色不对（红蓝互换）

理论上不会发生（BGR8 / RGB8 / BitMask 三种 GOP 格式都做了正确转换）。
如果真遇到，请提供 `DEBUG=1` 的输出，里面有像素格式信息。

### 6.2 画面被拉伸、有黑边、被裁掉

调 `SCALE`：

| 想要的效果 | 写法 |
|---|---|
| 原样居中，不缩放 | `SCALE=native`（帧分辨率和屏幕一致时用这个最好） |
| 完整显示，四周留黑边 | `SCALE=fit` |
| 铺满屏幕，允许裁掉边缘 | `SCALE=fill` |
| 强行拉伸填满 | `SCALE=stretch` |

### 6.3 动画卡顿

- 把帧导出成屏幕原生分辨率 + `SCALE=native`（最重要的优化，避免每帧软件缩放）
- `FILTER=nearest`（比 `bilinear` 快）
- 降低分辨率和帧数
- 用 `.baa` 而不是 BMP 序列（BMP 每帧都要重新打开文件 + 解码头部）

### 6.4 一直播放内置的转圈动画

说明素材没被找到。逐项检查：

1. `\EFI\BootAnim\anim.baa` 真的存在吗？（大小是不是 0）
2. `bootanim.cfg` 里的 `ANIM=` 写对了吗？
   相对路径是**相对配置文件所在目录**的，所以 `ANIM=anim.baa` 表示
   `\EFI\BootAnim\anim.baa`。
3. 用 `python tools/baanim.py info anim.baa` 验证文件没坏
   （应该输出 `decode : OK`）。
4. `DEBUG=1` 看具体是哪一步失败。

## 7. 编译相关

### MSVC 报源文件乱码 / 奇怪的语法错误

源码里有中文注释（UTF-8）。MSVC 默认按系统代码页解析没有 BOM 的源文件，
在中文系统上会读成乱码，甚至某个字节被当成行尾续行符导致后面的代码被吞掉。

`BootAnim.inf` 里已经加了 `/utf-8`。如果你是手工编译，请自己带上：

```bat
cl /utf-8 ...
```

GCC 默认按 UTF-8 解析，一般不需要额外参数（Makefile 里也显式加了
`-finput-charset=UTF-8`）。

### `build` 报找不到 `BootAnimPkg`

`build-edk2.bat` 会自动把源码和工程文件复制到 `<edk2>\BootAnimPkg\`。
如果那一步失败，通常是 EDK2 目录放在了 `C:\Program Files\` 下面没有写权限，
换一个普通目录（比如 `C:\edk2`）即可。

### `edksetup.bat` 失败

Windows 需要装 Visual Studio 的 **"使用 C++ 的桌面开发"** 工作负载；
Linux 需要 `build-essential uuid-dev nasm acpica-tools`。
新版 EDK2 还需要 Python **3.10+**（3.12 有可能因为 `antlr` 版本报错，
用 3.10/3.11 最稳）。

## 8. 彻底放弃：把 ESP 恢复干净

1. 跑 `Uninstall-BootAnim.ps1`（能进 Windows 的话）
2. 或者按 §2.2 手工改名
3. 再手工删掉素材目录：

```bat
rmdir /s /q S:\EFI\BootAnim
```

4. 如果之前用过 `-AlsoFallbackPath`，还要还原 `\EFI\Boot\bootx64.efi`：

```bat
del S:\EFI\Boot\bootx64.efi
ren S:\EFI\Boot\bootx64-orig.efi bootx64.efi
```
